# Actors Data Structure

This directory contains the actor and organization data for the Babylon game.

## Structure

The data is now split into individual files for better maintainability:

```
public/data/
├── actors.json              # Index file with references to individual files
├── actors-full.json         # Full combined file (generated, for client-side use)
├── actors.json.backup       # Backup of original monolithic file
├── actors/                  # Individual actor JSON files
│   ├── ailon-musk.json
│   ├── sam-AIltman.json
│   └── ... (64 total)
├── organizations/           # Individual organization JSON files
│   ├── openai.json
│   ├── anthropic.json
│   └── ... (52 total)
└── relationships/           # Individual relationship JSON files
    ├── ailon-musk_sam-AIltman.json
    ├── ailon-musk_mark-zuckerborg.json
    └── ... (332 total)
```

## Usage

### Server-Side (Node.js)

Use the actors loader utility:

```typescript
import { loadActorsData, loadActor, loadOrganization, loadRelationship } from '@/lib/data/actors-loader';

// Load all actors, organizations, and relationships
const data = loadActorsData();
console.log(data.actors.length); // 64
console.log(data.organizations.length); // 52
console.log(data.relationships.length); // 332

// Load a single actor
const actor = loadActor('ailon-musk');

// Load a single organization
const org = loadOrganization('openai');

// Load a relationship between two actors (alphabetical order)
const relationship = loadRelationship('ailon-musk', 'sam-AIltman');
```

### Client-Side (Browser)

Use the pre-built combined file:

```typescript
const response = await fetch('/data/actors-full.json');
const data = await response.json();
```

Or use the API endpoint:

```typescript
const response = await fetch('/api/actors');
const data = await response.json();
```

## Files

### actors.json

Index file containing references to individual actor, organization, and relationship files:

```json
{
  "actors": [
    { "id": "ailon-musk", "file": "./actors/ailon-musk.json" },
    ...
  ],
  "organizations": [
    { "id": "openai", "file": "./organizations/openai.json" },
    ...
  ],
  "relationships": [
    { "id": "ailon-musk_sam-AIltman", "file": "./relationships/ailon-musk_sam-AIltman.json" },
    ...
  ]
}
```

### actors-full.json

**Generated file** - Do not edit manually. This file is automatically generated from the individual files during the build process.

Contains the full combined actors and organizations data for client-side use.

### Individual Files

Each actor, organization, and relationship has its own JSON file in their respective directories.

**Actors:** `public/data/actors/<actor-id>.json`
**Organizations:** `public/data/organizations/<org-id>.json`
**Relationships:** `public/data/relationships/<actor1-id>_<actor2-id>.json` (alphabetically ordered)

#### Adding New Actors
1. Create a new file in `public/data/actors/` with the actor ID as the filename
2. Add reference to `actors.json`
3. Run `bun run scripts/build-actors-json.ts` to regenerate the full file

#### Adding New Relationships
1. Create a new file in `public/data/relationships/` with IDs in alphabetical order: `actor1_actor2.json`
2. Add reference to `actors.json` relationships section
3. Run `bun run scripts/build-actors-json.ts` to regenerate the full file

Example relationship file structure:
```json
{
  "actor1Id": "ailon-musk",
  "actor2Id": "sam-AIltman",
  "relationshipType": "rivals",
  "strength": 0.8,
  "sentiment": -0.5,
  "history": "Competing for AI dominance",
  "actor1FollowsActor2": true,
  "actor2FollowsActor1": true
}
```

## Scripts

### Generate relationships between actors
```bash
bun run scripts/generate-relationships.ts
```

Creates relationships based on:
- Shared affiliations (same organizations)
- Tier compatibility (similar tiers interact more)
- Domain overlap (same industry)
- Personality compatibility

### Rebuild actors-full.json from individual files
```bash
bun run scripts/build-actors-json.ts
```

This is automatically run during `bun run build` via the `prebuild` script.

Combines all individual files (actors, organizations, relationships) into a single file for client-side use.

## Benefits

1. **Easier to Edit**: Each actor/org/relationship is in its own file, making it easier to find and modify
2. **Better Git Diffs**: Changes to individual entities don't affect the entire file
3. **Reduced Merge Conflicts**: Multiple people can edit different entities simultaneously
4. **Better Organization**: Clear separation between actors, organizations, and relationships
5. **Lazy Loading**: Ability to load individual entities on-demand (future optimization)
6. **Relationship Management**: Named by both actors (alphabetically) for easy lookup

## Migration

The original monolithic `actors.json` has been backed up to `actors.json.backup`. All code has been updated to use the new structure via the actors-loader utility.
